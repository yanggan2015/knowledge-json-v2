# PCI 驱动绑定：从 pci_register_driver 到 probe 的 ID 表匹配

`lspci` 能看到设备但 `dmesg` 无 probe、BAR 映射为 0、DMA 偶发损坏：多半卡在 **PCI 总线匹配与资源申请**，不是业务寄存器读写。本文沿 **`pci_register_driver` → `pci_match_device` → `pci_device_probe` → 驱动 `probe`** 走通绑定，对照 `pci_device_id` 与 `lspci -nn` 排障。

## 源码锚点

| 路径 | 作用 |
|------|------|
| `include/linux/pci.h` | `struct pci_driver`、`struct pci_device_id`、`pci_register_driver` |
| `drivers/pci/pci-driver.c` | 注册、`pci_device_probe`、`local_pci_probe` |
| `drivers/pci/search.c` | `pci_match_device`、`pci_bus_match` |
| `drivers/base/dd.c` | `really_probe`、驱动绑定通用逻辑 |
| `drivers/pci/pci.c` | `pci_enable_device`、`pci_request_regions` |
| `Documentation/PCI/` | PCI 驱动编写指南 |

结构骨架：

```c
/* include/linux/pci.h */
struct pci_driver {
	const char		*name;
	const struct pci_device_id *id_table;   /* 匹配表 */
	int (*probe)(struct pci_dev *dev, const struct pci_device_id *id);
	void (*remove)(struct pci_dev *dev);
	struct device_driver driver;
};

struct pci_device_id {
	__u32 vendor, device;
	__u32 subvendor, subdevice;
	__u32 class, class_mask;
	kernel_ulong_t driver_data;
};

#define PCI_DEVICE(vend, dev) \
	.vendor = (vend), .device = (dev), \
	.subvendor = PCI_ANY_ID, .subdevice = PCI_ANY_ID
```

## 调用链

```text
module_init / pci_register_driver(pdrv)
  → driver_register(&pdrv->driver)
      → bus_add_driver
          → driver_attach
              → 遍历 pci_bus 上 device
                  → pci_bus_match(dev, drv)          /* drivers/pci/search.c */
                      → pci_match_device(pci_dev, id_table)
                          → vendor/device/class 掩码匹配
                  → really_probe (dd.c)
                      → pci_device_probe
                          → local_pci_probe
                              → pdrv->probe(pci_dev, id)

典型 probe 内资源路径：
  pci_enable_device(dev)
  → pci_request_regions(dev, DRV_NAME)   /* 占 BAR，防冲突 */
  → pci_set_master(dev)                  /* 允许 Bus Master */
  → pci_iomap(pci_dev, bar, len) / pcim_iomap
  → 注册 irq、初始化 DMA（dma_alloc_coherent 等）
```

热插拔 / 启动枚举侧：

```text
pci_scan_bus → pci_device_add
  → device_add
      → bus_probe_device
          → 同上 pci_match → probe
```

## 重点知识

**1. 匹配靠 `id_table`，不是设备名**  
`lspci -nn` 显示 `8086:15b8` 时，驱动表需写 `PCI_DEVICE(0x8086, 0x15b8)` 或带 `class` 掩码。`subvendor/subdevice` 用 `PCI_ANY_ID` 可放宽子系统 ID。表末要有空终止项。

**2. BAR 与 `pci_request_regions` 顺序**  
未 `request_regions` 时，另一驱动或用户工具可能同时映射同一 BAR。`pci_enable_device` 配置命令寄存器使能 MMIO/IO；`pci_set_master` 打开总线主控，否则 DMA 发不出去。

**3. `-EPROBE_DEFER` 与依赖**  
probe 里若 `devm_clk_get` / `pcim_enable_device` 依赖尚未就绪的 provider，应返回 `-EPROBE_DEFER`，内核推迟重试。盲目返回 `-ENODEV` 会导致设备永久不绑定。

**4. 观测命令**

```bash
lspci -nn | grep -i eth
lspci -vv -s 0000:03:00.0    # 看 BAR、驱动绑定
ls -l /sys/bus/pci/devices/0000:03:00.0/driver
cat /sys/bus/pci/devices/0000:03:00.0/enable
dmesg | grep -iE 'pci|probe|BAR|defer'
cat /sys/kernel/debug/devices_deferred   # 需 debugfs
```

Kconfig：`CONFIG_PCI` 及具体驱动 `CONFIG_*` 须开启；模块需 `modprobe` 或内核内置。

**5. 设计意图与踩坑**  
- **意图**：用标准化 vendor/device/class 表自动绑定，热插拔与 ACPI/DT 解耦。  
- **坑**：`id_table` 漏子设备 ID，OEM 卡 `subdevice` 不同导致不匹配。  
- **坑**：64-bit BAR 未检查 `pci_resource_len`，映射长度错误。  
- **坑**：未 `pci_set_master`，DMA 看似配置正确但硬件不发包。  
- **坑**：MSI/MSI-X 与共享 legacy IRQ 混用，中断从不触发。
