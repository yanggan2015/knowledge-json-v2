# 驱动中断与定时：从 request_threaded_irq 到 hrtimer 回调

外设丢中断、下半部太重拖垮实时、或 `mod_timer` 不准：根因往往在 **硬中断上下文约束** 与 **定时器类型选错**。本文沿 **`request_threaded_irq` → 硬中断/线程中断 → `hrtimer`/`timer_list`** 理清驱动侧该在哪一层做事，便于对照 `/proc/interrupts` 与 ftrace 验证。

## 源码锚点

| 路径 | 作用 |
|------|------|
| `include/linux/interrupt.h` | `request_irq`、`request_threaded_irq`、`IRQF_*` |
| `kernel/irq/manage.c` | 申请/释放 IRQ、线程化中断安装 |
| `include/linux/timer.h` | `timer_list`、`timer_setup`、`mod_timer` |
| `kernel/time/timer.c` | 低分辨率定时器轮 |
| `include/linux/hrtimer.h` / `kernel/time/hrtimer.c` | 高分辨率定时器 |
| `Documentation/core-api/irq/irq-domain.rst` 等 | IRQ 域与映射（DT 场景） |

申请线程化中断（概念）：

```c
/* include/linux/interrupt.h */
int request_threaded_irq(unsigned int irq, irq_handler_t handler,
			 irq_handler_t thread_fn, unsigned long flags,
			 const char *name, void *dev);

/* handler：硬中断上下文（可 NULL，表示仅线程）
 * thread_fn：IRQ 线程中运行，可睡眠
 */
```

定时器骨架：

```c
/* 低精度：jiffies */
timer_setup(&dev->timer, my_timer_cb, 0);
mod_timer(&dev->timer, jiffies + msecs_to_jiffies(10));

/* 高精度：ktime */
hrtimer_init(&dev->hr, CLOCK_MONOTONIC, HRTIMER_MODE_REL);
dev->hr.function = my_hr_cb;
hrtimer_start(&dev->hr, ms_to_ktime(1), HRTIMER_MODE_REL);
```

## 调用链

```text
硬件 IRQ 线置位
  → 架构入口 (如 handle_domain_irq)
      → desc->handle_irq
          → 驱动 primary handler (若注册)
              → 清状态 / 屏蔽 / 返回 IRQ_WAKE_THREAD 或 IRQ_HANDLED
          → irq 线程 (thread_fn)          /* 可阻塞：读 I2C、拷缓冲 */
              → wake_up / complete / queue_work

驱动定时需求
  → mod_timer / hrtimer_start
      → 时间子系统到期
          → timer_list 回调（软中断/软定时上下文，不可长时间睡眠）
          → hrtimer 回调（硬/软 irq 上下文，取决于模式；通常不可睡眠）
              → 需睡眠的工作 → queue_work / 唤醒进程
```

DT 取中断号：

```text
platform_get_irq(pdev, 0)
  或 irq_of_parse_and_map(np, 0)
    → 映射到 Linux IRQ 号后再 request_*
```

## 重点知识

**1. 硬中断里只做「最短必要」**  
硬中断上下文：**不可调度、不可睡眠**。只做读寄存器、清中断源、搬少量数据或 `IRQ_WAKE_THREAD`。耗时解析、加锁可能睡的路径、打印过多 `printk` 都应放到 `thread_fn` 或 `workqueue`。

**2. `request_threaded_irq` 优于「硬中断里塞一切」**  
`handler` + `thread_fn` 分离后，主 handler 返回 `IRQ_WAKE_THREAD` 即可。若 `handler` 传 `NULL`，内核使用默认主 handler，强制线程化——适合慢速总线外设。共享中断必须用 `IRQF_SHARED`，且 `dev_id` 非 NULL，释放时指针一致。

**3. `timer_list` vs `hrtimer`**  
- `timer_list`：基于 jiffies，适合 ≥1 tick 的超时、延后释放、粗粒度轮询。  
- `hrtimer`：纳秒级、周期采样、精确截止时间。  
两者回调里同样不能睡眠；需要睡眠就投递 work。周期 hrtimer 在回调里返回 `HRTIMER_RESTART` 并 `hrtimer_forward_now`。

**4. 配置与观测**

```bash
cat /proc/interrupts | grep -i <name>     # 计数是否增长
cat /proc/irq/<n>/affinity                # 绑核
# 延迟与路径
trace-cmd record -e irq_handler_entry -e irq_handler_exit sleep 2
# 或
ftrace: irqsoff / preemptirqsoff（诊断关中断过久）
# 定时器风暴
cat /proc/timer_list | head               # 调试用，输出大
dmesg | grep -iE 'irq|threaded'
```

设备树：`interrupts` / `interrupts-extended` 与 `interrupt-parent` 配错会导致申请到错误虚号或 probe 失败。

**5. 设计意图与踩坑**  
- **意图**：上半部保响应，下半部保可睡眠工作；定时器表达「未来某时刻再跑」。  
- **坑**：在硬中断里 `mutex_lock` / `kmalloc(GFP_KERNEL)` → 休眠或警告。  
- **坑**：忘记清中断状态 → 中断风暴，`/proc/interrupts` 狂涨、系统卡顿。  
- **坑**：`free_irq` 与模块卸载竞态：应先禁用设备中断再释放。  
- **坑**：用 jiffies 定时器做 100µs 周期控制——分辨率不够，应改 hrtimer 或硬件定时器。

## Checklist

- [ ] 能区分 primary handler 与 `thread_fn` 的约束，并指出 `request_threaded_irq` 所在头文件/实现文件
- [ ] `/proc/interrupts` 中对应行在刺激外设后计数增加
- [ ] 共享中断使用 `IRQF_SHARED` 且 `dev_id` 唯一、申请释放一致
- [ ] 回调内无睡眠；睡眠路径走 workqueue / IRQ 线程
- [ ] 按精度需求在 `timer_list` 与 `hrtimer` 间正确选型，并验证到期行为
- [ ] 卸载路径：停定时器（`del_timer_sync`/`hrtimer_cancel`）→ `free_irq` → 再释放设备
