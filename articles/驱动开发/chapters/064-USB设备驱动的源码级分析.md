# USB 接口驱动：从 usb_register_driver 到 URB 提交的绑定路径

设备 `lsusb` 可见但无 `/dev`、bulk 传输 `-ENODEV`、枚举后反复 disconnect：问题常在 **USB 总线匹配与 URB 生命周期**，而不是端点号手写错误 alone。本文沿 **`usb_register_driver` → `usb_probe_interface` → `usb_submit_urb`** 走通接口驱动绑定与一次传输，对照 `usb_device_id` 与 `lsusb -v` 排障。

## 源码锚点

| 路径 | 作用 |
|------|------|
| `include/linux/usb.h` | `struct usb_driver`、`struct usb_device_id`、`usb_register_driver` |
| `drivers/usb/core/driver.c` | 注册、`usb_probe_interface`、`usb_unbind_interface` |
| `drivers/usb/core/message.c` | `usb_submit_urb`、`usb_kill_urb` |
| `drivers/usb/core/hub.c` | 枚举、端口状态（理解 disconnect 根因） |
| `drivers/usb/core/config.c` | 描述符解析、接口 alt setting |
| `Documentation/driver-api/usb/` | USB 驱动 API |

结构骨架：

```c
/* include/linux/usb.h */
struct usb_driver {
	const char *name;
	int (*probe)(struct usb_interface *intf,
		     const struct usb_device_id *id);
	void (*disconnect)(struct usb_interface *intf);
	const struct usb_device_id *id_table;
	/* suspend/resume 等可选 */
};

struct usb_device_id {
	__u16 match_flags;
	__u16 idVendor;
	__u16 idProduct;
	__u8  bDeviceClass;
	/* … bInterfaceClass 等 */
};

struct urb {
	struct usb_device *dev;
	unsigned int pipe;       /* 端点 + 方向 + 类型 */
	void *transfer_buffer;
	dma_addr_t transfer_dma;
	usb_complete_t complete;
	void *context;
	/* … */
};
```

## 调用链

```text
module_init / usb_register_driver(driver)
  → driver_register
      → driver_attach
          → 遍历 usb 总线 device（接口级）
              → usb_driver_match_id(intf, id_table)
              → really_probe
                  → usb_probe_interface
                      → driver->probe(intf, id)

用户态 open 或驱动主动 I/O：
  驱动 probe 内 usb_find_endpoint / 解析描述符
  → usb_alloc_urb
  → usb_fill_bulk_urb / usb_fill_int_urb
  → usb_submit_urb(urb, GFP_KERNEL)
      → hcd->driver->urb_enqueue
          → 硬件 DMA / 中断完成
              → urb->complete(urb)
                  → usb_free_urb / 唤醒等待队列

断开：
  hub 事件 / 用户拔出
  → usb_disconnect
      → driver->disconnect(intf)
          → usb_kill_urb（必须先停 URB）
```

## 重点知识

**1. USB 驱动绑在 interface，不是 device 根**  
一个物理设备可有多 interface（复合设备）。`id_table` 可匹配 `idVendor/idProduct`，也可用 `USB_INTERFACE_INFO` 按 class/subclass/protocol 匹配。`lsusb -t` 看接口树。

**2. URB 是异步核心**  
`usb_submit_urb` 立即返回；完成在中断上下文调 `complete`。在 `complete` 里不能睡眠；重提交需防 unplug 后访问已释放的 `usb_device`。`disconnect` 里必须 `usb_kill_urb` 等待在飞 URB 结束。

**3. 端点与 pipe**  
`usb_rcvbulkpipe(dev, endpoint)` 把地址与方向编码进 `pipe`。端点号来自描述符，不要假设 bulk 永远是 `0x01/0x81`；用 `usb_endpoint_num` / `usb_find_endpoint` 解析。

**4. 观测命令**

```bash
lsusb -v -d vv:pp          # 描述符、端点、interface
lsusb -t                   # 拓扑
ls -l /sys/bus/usb/devices/*/driver
cat /sys/kernel/debug/usb/devices   # 需 debugfs
dmesg | grep -iE 'usb|urb|probe|disconnect'
modinfo <your_driver> | grep alias   # 动态 ID 表
```

用户态：`usbmon`（`CONFIG_USB_MON`）抓包；`udevadm monitor` 看 plug 事件。

**5. 设计意图与踩坑**  
- **意图**：主机栈统一枚举与带宽调度；URB 抽象各 HCD 差异。  
- **坑**：`probe` 里同步 `usb_control_msg` 阻塞过久，拖慢枚举。  
- **坑**：未在 `disconnect` kill URB → unplug 后 use-after-free。  
- **坑**：DMA 缓冲区未用 `usb_alloc_coherent`，在部分架构上 cache 不一致。  
- **坑**：忽略 alt setting，接口未 `usb_set_interface` 导致端点未激活。  
- **坑**：复合设备只绑了一个 interface，另一 interface 被别的驱动占用或未驱动。

## Checklist

- [ ] 能口述 `usb_register_driver` → `usb_probe_interface` → `probe` 的调用位置
- [ ] `lsusb -nn` 与 `usb_device_id` / `MODULE_DEVICE_TABLE(usb, …)` 一致
- [ ] 确认驱动匹配的是正确 interface（复合设备多接口）
- [ ] 端点号来自描述符解析，而非硬编码
- [ ] 每个 `submit_urb` 有对应 `kill_urb`/`free` 路径，`disconnect` 可安全退出
- [ ] bulk/int 传输用正确 pipe 方向；控制传输注意 `wValue/wIndex` 与设备协议一致
