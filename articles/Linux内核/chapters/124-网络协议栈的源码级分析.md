# TCP 发包路径：从 sock_sendmsg 到网卡 NAPI 的 sk_buff 旅程

跨洲吞吐上不去、`connect` 超时却 `ping` 正常、收包 CPU 飙在 `softirq`：这些多半要沿 **socket → 协议栈 → qdisc → 驱动** 逐层对照，而不是只调 `sysctl`。本文沿 **`sock_sendmsg` → `tcp_sendmsg` → `ip_queue_xmit` → `dev_queue_xmit` → NAPI 收包** 走通主路径，便于用 `ss`/`tcpdump`/`perf` 定位瓶颈。

## 源码锚点

| 路径 | 作用 |
|------|------|
| `net/socket.c` | `sock_sendmsg`、`__sys_sendto` 等系统调用入口 |
| `net/ipv4/tcp.c` | `tcp_sendmsg`、`tcp_v4_connect`、拥塞控制挂钩 |
| `net/ipv4/ip_output.c` | `ip_queue_xmit`、`ip_local_out` |
| `net/core/skbuff.c` | `struct sk_buff` 分配与生命周期 |
| `net/core/dev.c` | `dev_queue_xmit`、`netif_receive_skb` |
| `net/sched/sch_generic.c` | qdisc 排队与出队 |
| `include/linux/skbuff.h` | `sk_buff` 头字段 |
| `Documentation/networking/` | 网络子系统总览 |

核心对象：

```c
/* include/linux/skbuff.h — 包在各层间传递的载体 */
struct sk_buff {
	struct sk_buff		*next;
	struct sk_buff		*prev;
	unsigned char		*head;
	unsigned char		*data;
	unsigned char		*tail;
	unsigned char		*end;
	unsigned int		len;
	struct net_device	*dev;
	/* … */
};

/* include/linux/netdevice.h — 收包软中断入口之一 */
struct napi_struct {
	int (*poll)(struct napi_struct *, int);
	unsigned int		state;
	int			weight;
	/* … */
};
```

发包骨架（逻辑）：

```c
/* net/socket.c → net/ipv4/tcp.c */
sock_sendmsg(sock, &msg)
  → tcp_sendmsg(sock, &msg, size)
      → tcp_write_xmit / tso_fragment
      → ip_queue_xmit(skb)
          → ip_local_out → dev_queue_xmit(skb)
              → qdisc -> ndo_start_xmit
```

## 调用链

```text
send()/write() 用户态
  → __sys_sendto / __sys_sendmsg          /* net/socket.c */
      → sock_sendmsg
          → tcp_sendmsg                   /* net/ipv4/tcp.c */
              → 拷贝用户数据到 skb，更新 snd_wnd/拥塞窗口
              → tcp_transmit_skb → ip_queue_xmit
                  → ip_local_out
                      → __ip_local_out → nf_hook → dst_output
                          → ip_finish_output
                              → dev_queue_xmit            /* net/core/dev.c */
                                  → __dev_queue_xmit
                                      → qdisc_run（pfifo_fast/fq 等）
                                          → netdev_start_xmit
                                              → 驱动 ndo_start_xmit → DMA

收包（对称路径，简化）
  NIC 硬中断 → napi_schedule
      → NET_RX_SOFTIRQ → napi_poll
          → netif_receive_skb / __netif_receive_skb_core
              → 协议 demux（ipv4_rcv → tcp_v4_rcv）
                  → tcp_rcv_established → sk_data_ready
                      → 唤醒用户态 read()
```

## 重点知识

**1. sk_buff 贯穿全栈**  
每层通过推拉 `data` 指针增减协议头，而不是反复拷贝整包。排障时 `skb` 泄漏或 `kfree_skb` 过早会导致随机崩溃；用 `dropwatch`、`bpftrace` 跟踪 `kfree_skb` 路径。

**2. socket 与 sock 分层**  
`struct socket` 是 BSD 层；`struct sock` / `struct tcp_sock` 承载协议状态（窗口、重传队列、`sk_write_queue`）。`connect` 超时先看 `tcp_v4_connect` 是否卡在 SYN 重传（半连接队列、`syncookies`），而非盲目加 `rmem`。

**3. 出队必经 qdisc**  
`dev_queue_xmit` 把 skb 交给网卡对应的 `netdev_queue` 与 qdisc。BBR 等拥塞算法常要求 **fq** qdisc 配合；只改 `tcp_congestion_control` 不换 qdisc，效果可能打折。

**4. NAPI 把收包从硬中断挪到软中断**  
硬中断里只做 `napi_schedule`，实际收包在 `NET_RX_SOFTIRQ`。`softirq` CPU 飙高时查 RSS/RPS、`netdev_budget`、是否单队列 NIC 成为瓶颈。

**5. 观测命令**

```bash
ss -tin state established    # 看 cwnd/rtt/wmem/rmem
ss -s                       # 汇总重传、半连接
sysctl -a | grep -E 'net.core|net.ipv4.tcp'
cat /proc/net/softnet_stat  # 每 CPU 收包 drop
ethtool -S eth0 | grep -i drop
ethtool -g eth0             # ring 大小
tcpdump -i any -nn 'tcp[tcpflags] & tcp-syn != 0'
perf top -e softirq_entry -a
```

**6. 设计意图与踩坑**  
- **意图**：分层解耦协议与驱动；sk_buff 统一内存模型；NAPI 限制中断风暴。  
- **坑**：`somaxconn` / `tcp_max_syn_backlog` 过小 → `connect` 超时或 SYN 丢。  
- **坑**：`rp_filter=1` 在非对称路由环境误丢合法包。  
- **坑**：GRO 聚合后 `tcpdump` 见「巨帧」，误判网卡异常。  
- **坑**：只调 `net.ipv4.tcp_rmem` 不改 BDP（带宽×延迟），缓冲区仍不够。
