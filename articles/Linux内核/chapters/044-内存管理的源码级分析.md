# 缺页与 page cache：从 handle_mm_fault 到 do_swap_page 的源码路径

`mmap` 后第一次读写才真正占物理页；文件读大多先进 **page cache**。搞不清 **匿名缺页 / 文件缺页 / swap-in**，就会在 OOM、抖动、`pgmajfault` 飙升时误判。本文按 **`handle_mm_fault()`** 主路径把三类缺页钉到具体文件。

## 源码锚点

| 路径 | 作用 |
|------|------|
| `arch/x86/mm/fault.c` 或 `arch/arm64/mm/fault.c` | 架构侧缺页入口（`do_page_fault` / `do_mem_abort`） |
| `mm/memory.c` | `handle_mm_fault()`、`handle_pte_fault()` |
| `mm/filemap.c` | 文件映射、`filemap_fault` |
| `mm/swapfile.c` / `mm/page_io.c` | swap 读写 |
| `mm/mempool.c` / `mm/slub.c` | 内核对象分配（对比页分配） |
| `include/linux/mm.h` | `vm_fault`、`vm_area_struct` 相关声明 |
| `Documentation/vm/` | 内存子系统文档 |

缺页处理入口（概念）：

```c
/* mm/memory.c */
vm_fault_t handle_mm_fault(struct vm_area_struct *vma,
			   unsigned long address, unsigned int flags,
			   struct pt_regs *regs)
{
	/* ... */
	return __handle_mm_fault(vma, address, flags);
}
```

VMA 与 mm：

```c
/* include/linux/mm_types.h — 概念字段 */
struct vm_area_struct {
	unsigned long vm_start, vm_end;
	struct mm_struct *vm_mm;
	pgprot_t vm_page_prot;
	unsigned long vm_flags;	/* VM_READ/WRITE/EXEC/... */
	const struct vm_operations_struct *vm_ops;
};
```

## 调用链

```text
用户访问未映射/权限不足的 VA
  → 架构异常入口 (do_page_fault / do_translation_fault …)
      → handle_mm_fault(vma, addr, flags, regs)     /* mm/memory.c */
          → __handle_mm_fault
              → 遍历 PGD→P4D→PUD→PMD→PTE
              → handle_pte_fault
                  ├─ PTE 空 + 匿名 VMA
                  │     → do_anonymous_page          /* 零页/新页 */
                  ├─ PTE 空 + 文件 VMA
                  │     → do_fault → filemap_fault   /* page cache */
                  ├─ PTE 为 swap entry
                  │     → do_swap_page               /* 换入 */
                  └─ 写只读 PTE (COW)
                        → do_wp_page
```

文件读路径（与缺页交汇）：

```text
read(fd)
  → vfs_read → filemap_read / generic_file_buffered_read
      → page cache 命中则拷贝；未命中则提交读 bio
缺页走 filemap_fault 时复用同一套 page cache 页
```

## 重点知识

**1. 缺页不是「分配失败」的同义词**  
多数缺页是 **按需填充**：匿名页、文件页、COW。真正的压力在回收与 OOM：`kswapd`、直接回收、`out_of_memory()`。

**2. Major vs Minor**  
- **Minor**：页已在 RAM（含 page cache），只补页表。  
- **Major**：需读盘 / swap-in。  
观测：`/proc/vmstat` 的 `pgmajfault`、`pgpgin`；`ps -o min_flt,maj_flt`。

**3. page cache 与写回**  
脏页经 `balance_dirty_pages` / `wb` 写回。嵌入式小内存机上脏比过高会拖死写路径——调 `dirty_ratio` / `dirty_bytes` 前先看 `Dirty`/`Writeback`（`/proc/meminfo`）。

**4. 配置与验证**

```bash
grep -E 'pgfault|pgmajfault|pswpin|pswpout' /proc/vmstat
cat /proc/meminfo | grep -E 'MemAvailable|Cached|Swap|Dirty'
# 单进程
cat /proc/<pid>/status | grep -E 'VmRSS|VmSwap'
cat /proc/<pid>/smaps_rollup
# 压力时
echo 1 > /proc/sys/vm/drop_caches   # 仅实验机
```

**5. 设计意图与踩坑**  
- **意图**：延迟分配 + 共享 page cache，提高利用率。  
- **坑**：未设 `oom_score_adj`，OOM 杀掉关键守护进程。  
- **坑**：THP 在延迟敏感库上偶发数毫秒合并阻塞。  
- **坑**：把 cache 增长当成泄漏——`Cached` 可回收，优先看 `MemAvailable`。
