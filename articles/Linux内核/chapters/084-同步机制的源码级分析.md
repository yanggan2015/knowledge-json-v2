# RCU 读多写少：从 rcu_read_lock 到 call_rcu 的宽限期

链表/哈希在读路径上被疯狂遍历时，自旋锁会把多核读放大成串行。**RCU** 的约定是：读侧几乎无锁，写者更新指针后把旧对象交给 `call_rcu()`，等一个 **宽限期（grace period）** 再释放。本文把 API 钉到头文件与 tree RCU 实现入口，并列出最常见的 use-after-free 用法错误。

## 源码锚点

| 路径 | 作用 |
|------|------|
| `include/linux/rcupdate.h` | `rcu_read_lock/unlock`、`rcu_dereference`、`rcu_assign_pointer` |
| `include/linux/rculist.h` | 链表 RCU 辅助宏 |
| `kernel/rcu/tree.c` | tree RCU：宽限期、回调催熟 |
| `kernel/rcu/update.c` | `call_rcu`、`synchronize_rcu` 等 |
| `Documentation/RCU/` | 概念与 Checklist 文档 |

读侧与解引用：

```c
/* 典型读路径 */
rcu_read_lock();
p = rcu_dereference(global_ptr);
if (p)
	do_something(p);
rcu_read_unlock();
```

写侧发布与回收：

```c
/* 发布新对象 */
rcu_assign_pointer(global_ptr, new_obj);

/* 回收旧对象：等所有读侧退出临界区 */
call_rcu(&old_obj->rcu, old_obj_free_cb);
/* 或同步等待 */
synchronize_rcu();
kfree(old_obj);
```

## 调用链

```text
读者:
  rcu_read_lock()
    → 禁抢占 / 记 note（视配置）
    → rcu_dereference(p)     /* READ_ONCE + 依赖屏障语义 */
  rcu_read_unlock()

写者替换:
  分配并初始化 new
  rcu_assign_pointer(gp, new)   /* 写屏障，保证字段先于指针可见 */
  call_rcu(&old->rcu, cb)
      → 回调挂入 per-CPU 列表
          → GP 推进（tree RCU quiescent state）
              → 宽限期结束后执行 cb → kfree

阻塞式写者:
  synchronize_rcu()  /* 当前上下文睡眠直到 GP 结束 */
```

## 重点知识

**1. 读侧规则**  
`rcu_read_lock` 临界区内 **不可睡眠**（经典 RCU）。需要睡眠用 `SRCU`（`srcu_read_lock`）。任意出口路径都要配对 `unlock`，否则宽限期无法结束，回调堆积拖垮内存。

**2. 必须成对使用的原语**  
- 读：`rcu_dereference`（或 list 宏）  
- 写：`rcu_assign_pointer`  
缺屏障的普通赋值会在弱序 CPU 上读到「指针已新、字段未初始化」的半成品。

**3. call_rcu vs synchronize_rcu**  
- `call_rcu`：异步，写者不等待，适合热路径。  
- `synchronize_rcu`：同步，简单但可能毫秒级阻塞。  
模块 unload 前常用 `rcu_barrier()` 等回调跑完。

**4. 与其它锁的分工**

| 场景 | 更合适 |
|------|--------|
| 读极多、写很少的查找结构 | RCU |
| 短临界区、可关抢占 | spinlock |
| 长临界区、可睡眠 | mutex |
| 读多写少但读侧要睡 | SRCU / rwsem |

**5. 配置与验证**

```bash
# lockdep + RCU 相关（调试内核）
# CONFIG_PROVE_RCU / CONFIG_DEBUG_OBJECTS_RCU_HEAD
dmesg | grep -i rcu
# 回调堆积迹象：rcu stall、内存持续上涨且 slab 指向待释放对象
cat /proc/rcu_* 2>/dev/null | head
sysctl -a 2>/dev/null | grep -i rcu | head
```

**6. 设计意图与踩坑**  
- **意图**：读扩展性优先，把同步成本推到写者与回收。  
- **坑**：`call_rcu` 之前就 `kfree`——典型 UAF。  
- **坑**：读侧持指针越过 `rcu_read_unlock` 再解引用。  
- **坑**：把 RCU 当「万能无锁」，写路径无互斥导致两个写者互踩。

## Checklist

- [ ] 读路径全部包在 `rcu_read_lock/unlock`（或 SRCU）内
- [ ] 指针发布用 `rcu_assign_pointer`，读取用 `rcu_dereference`
- [ ] 释放旧对象只通过 `call_rcu` / `synchronize_rcu` 之后
- [ ] 模块退出调用 `rcu_barrier`（若用了 `call_rcu`）
- [ ] 读侧临界区无睡眠、无主动调度依赖
- [ ] 写写之间另有互斥（锁或单一写者约定）
